## §P0 噪声测量

**状态（2026-10-20）：已完成。** 用户改为由主 Agent 直接推进，结论见 [P0 报告](../experiments/harness-hub/p0/report.md)：

- 受控对比在统计上可行，但多步任务的波动主要来自路径长度，需要按轨迹分层或折算到每轮；
- 两个任务的质量都在上限，需要 P4 的评测任务集；
- 工具失败全部是 Harness 接口摩擦。

### 目的

在配置完全固定的条件下，测量同一任务重复运行时四个判据的波动有多大，并据此算出"两个变体之间要相差多少、每边要跑多少次才能看出区别"。这决定后面的受控实验（P6）能不能做、要做多大。

**本阶段不改任何产品源码。** 脚本、夹具和结论放在 `experiments/harness-hub/p0/`；原始日志、模型输出和证据只放在 `.local/harness-hub-p0/`，不入库。

### 环境

- **使用平台已保存的渠道和默认 Flash 模型**。用户已授权，不必节省 token。
- **隔离运行**：参照 `.local/weekly-gateway-wording-20261020/verify.py` 的做法：
  - 使用和运行中 8077 服务相同的 Host 可执行文件，并记录它的 SHA-256；
  - 使用固定的 Goose；
  - 使用已保存模型配置的私有快照，以及独立的数据根目录；
  - 运行结束后删除快照。
- **不碰 8077 服务**：不修改它的数据、配置、Graph、授权和定时任务。如果隔离运行做不到，停下来报告，不要改用 8077 的数据目录。
- **不设预算**（用户决定 W4）。每个 Run 只设一个 900 秒的看门狗，防止测试脚本卡死。触发看门狗单独记为 `guard`，不算模型失败。

### 任务

夹具 Graph 和输入都用合成的公开数据，不接外部业务 Plugin。

| 任务 | 结构 | 测什么 |
| --- | --- | --- |
| T1 无工具 | 单个 AgentNode。提示词里直接给出固定输入（例如 30 个整数），要求通过 `final_result` 返回可以精确校验的结果（例如总和和最大的 5 个数） | 模型本身的波动 |
| T2 工具型 | AgentNode 后接一个确定性的校验 Op 节点。AgentNode 用授权的文件工具读取一个固定的输入目录（例如 10 个小文本文件），按规则统计，写出结果文件、读回，再提交 `final_result`；校验 Op 精确检查结果 | 工具调用和多节点调度的波动 |

- 每个任务的判定都必须是确定性的：通过或不通过。这作为任务质量的替代信号，也是 P4 评测任务集的第一批样本。
- 每个任务**串行**运行 **30 次**，同一时间只跑一个 Run，避免并发干扰耗时数据。记录每次的开始时间。

### 每个 Run 采集的指标

数据来源：Run 状态、节点 evidence 里的 `usage`（`goose_acp.rs` 里的 `evidence["usage"]`）、`notifications`，以及内核历史。

- **结局**：phase、outcome、reason；校验是否通过；
- **时间**：
  - Run 从创建到结算的墙钟时间；
  - 每个节点的 `elapsed_ms`；
  - 首 token 时间；
- **模型**：
  - 请求次数；
  - 输入、输出、缓存读写和总 token；
  - `cost_micros`（如果有上报）；
  - 压缩次数；
- **工具**：
  - 按工具统计调用次数和失败次数（从工具调用更新通知的状态判断）；
  - 如果能拿到，记录每次调用的耗时；
- **内核**：
  - 历史记录条数；
  - 按原因码统计的被拒提交、版本冲突。

**拿不到的指标同样重要。** 比如工具调用没有时间戳、拿不到某种 token，都要明确列出来，作为 P2 记录适配器的输入。

### 统计

对每个任务的每个指标，计算：

- n、均值、标准差、变异系数；
- 中位数、p10、p90、最小值、最大值；
- 漂移：指标和运行序号之间的 Spearman 相关，看是否随时间系统性变化。

对通过率，计算 Wilson 95% 区间。

计算**最小可检测差异**：两组对比，α = 0.05，检验力 0.8，每组 n = 10、30、100 时，能检测出的最小相对差异。

- 连续指标：用正态近似 `MDE ≈ 2.8 · sd · √(2/n)`，再除以均值；
- 通过率：用两比例检验。

### 产物

`experiments/harness-hub/p0/` 下：

- 运行脚本、分析脚本；
- `fixtures/`：Graph、输入、校验器；
- `runs.jsonl`：每个 Run 一行指标，**不含模型生成的文本**；
- `summary.json`；
- `report.md`，内容包括：
  - 环境身份：Host 和 Goose 的 SHA-256、模型标识；
  - 统计表；
  - 最小可检测差异表；
  - G0 结论；
  - 拿不到的指标清单；
  - 对 P6 样本量的建议。

### G0 判断

暂定目标：**每组 30 次时，token 和墙钟时间能检测出不超过 20% 的相对差异**。报告如实给出数字和结论；达不到也照实写，由审查方和用户决定后续怎么调整。

### 停止条件

- 超过 20% 的 Run 出现 Provider 或传输错误：停下来，报告错误分布；
- 出现任何对 8077 服务数据的写入：立即停止并报告。

## §P1 内核变更：时间、因果、配置、只读读取

**状态（2026-10-20）：已实现，两轮独立审查通过后（`e172e05`），又按第一性原理做了简化：删除全局序号和内核层的因果引用。简化版审查通过，新的冻结基点 C1 为 `9a5fa57`。** 下面是原任务书，第 2、3 项已被简化取代，见 [P1 验证与审查](../experiments/harness-hub/p1/verification.md)。

### 目的

让内核记录后续分析需要、但现在没有记录的事实。**内核只记录，不新增任何裁决规则，也不根据这些字段做判断。**

这是 `0859373` 之后第一次改 `anchor-kernel`。审查通过后，以 P1 的提交作为新的冻结基点（C1）。

### 不变量

- 现有的所有裁决结果不变：已有的内核测试和 workspace 测试全部通过，业务断言不放宽。
- 不新增 `Reason`、`Phase`、`Waiter`、`Action` 或新的 Store 种类；不新增第二个写入口，`Kernel::submit` 仍是唯一的改变入口。
- 内核代码里没有任何基于时间、配置摘要或因果引用的分支判断。
- Anchor 还没上生产：新字段一律可选，旧记录读出来是"未记录"，**不做迁移，也不拒绝旧记录**。分析侧把"未记录"当作"不适用"。

### 改动

1. **Clock 端口**
   - 新增 `Clock` trait，返回 Unix 纪元以来的 UTC 毫秒数；
   - 构造方式和 `with_probe` 一样提供 `with_clock`，默认使用系统时钟，所以现有的构造调用不用改；
   - `submit` 在持有写锁时取一次时间，写进 Stamp 的新字段（例如 `at`）；
   - 内核不保证时间单调：顺序以 `seq` 为准，时间只是记录。
2. **因果引用**
   - `Submission` 增加可选字段，引用引发这次提交的那条记录，形式为"资源 id + seq"；
   - 内核不校验它，原样写入历史。
3. **每次提交的配置摘要**
   - 删除全局的 `knobs`（`kernel.rs:52`、`:64`、`:79` 的 `set_knobs`；生产代码里没有调用，只有 `tests/constitution.rs:534` 在用）；
   - 改为每次提交由宿主提供一个可选的配置摘要，写进 Stamp，和 principal、cost 一样是宿主盖章的内容；
   - 具体是改 `submit` 的参数，还是把三项合成一个宿主盖章结构，由你根据调用点决定。约束是：仍然只有一个入口。
   - 在 P2 之前，Host 一律传"未提供"。
4. **资源创建也要可查**
   - 现在 `Kernel::create` 只写 `resource.json`，不写历史，所以 Run 是什么时候、用什么配置创建的查不到；
   - 要求：创建时间和配置摘要必须能从持久事实里得到；之后的每次提交都不能把它们弄丢，包括 Validator 生成新状态的时候；任何规则都不读取它们；
   - 可以写一条创建记录进历史，也可以作为资源上由内核维护的字段，由你选择，交回时说明理由，以及对探针重建、历史读取的影响。
5. **测量点**
   - Point 加上时间和配置摘要，用来替代 `knobs`；
   - 同步修改 Host 的探针重建，见 `kernel_probe.rs:95`。
6. **只读历史读取**
   - `FileStore` 增加只读访问：列出资源，按资源读取历史；
   - 不加锁，不创建任何文件或目录，不写入；
   - 跳过正在删除的资源和锁目录；
   - 只返回以换行结尾的完整记录，正在追加的半行不返回也不报错。
   - 中枢以后只通过它读取数据，不自己解析目录结构。

### 测试

- **新增内核测试**：
  - 固定时钟下，时间和 `seq` 正确写入；
  - 因果引用和配置摘要原样进入历史和测量点；
  - 创建事实可以查到，并且在多次提交、包括 Validator 改写状态之后仍然存在；
  - 旧格式的记录，也就是没有新字段的，能正常读出为"未记录"；
  - 只读读取在另一个写入者追加半行时只返回完整记录，并且不在目录里产生任何新文件；
  - 同一组提交序列在改动前后得到完全相同的裁决序列。
- **允许改动的断言**：`tests/constitution.rs:534` 从全局 knobs 改为每次提交的配置摘要。其他断言改动必须逐条列出理由。
