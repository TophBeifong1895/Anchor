# Anchor 宪法与架构

编制日期：2026-10-15。

| 部分 | 状态 |
| --- | --- |
| 宪法（第 1 节） | **定稿** |
| 架构（第 2–9 节） | **设计定稿**，由宪法推出 |
| 旋钮的具体集合（第 6 节） | **假设**，只能由数据确定 |
| 实施 | **未授权**；迁移顺序见第 10 节 |

本文是 Anchor 的最高设计依据。当前实现以 [architecture.md](architecture.md) 为准，进度只记 [开发台账](pilot-development-plan.md)。[以提交为细腰](submission-narrow-waist.md) 是本文的讨论前身，[收敛方案](convergence-development-plan.md) 是本文第 10 节的第一阶段。两者与本文冲突时，以本文为准。

**"完美"在这里的含义**：不是事先证明它正确，而是满足三个可检验的条件：每个组件都能从宪法推出，或者属于可整块替换的边缘；推到四个极限（第 7 节）时核心不需要改变；核心里没有可以删掉的东西。第 12 节给出持续检验的方法。

## 1. 宪法

> **不可靠的提议者在有边界的舞台上自由行动；确定性的代码负责裁决、记录和测量；被选择的改变才会留下。**

| 条文 | 对应的世界事实 | 它禁止的东西 |
| --- | --- | --- |
| **一、一切改变都是提交，由不是提议者的确定性代码裁决。** | 没有人能做自己的法官 | 模型的话直接成为事实；任何组件直接改写别人的状态 |
| **二、历史只追加；没有观察到的就是未知。** | 时间不可逆；信息是局部的 | 改写历史；把声明当事实；把未知当成功；自动重放结果未知的副作用 |
| **三、每件事都在有限的资源内，结束于有限的结果之一。** | 资源有限 | 永远运行、悄悄放弃、永远处于"进行中" |
| **四、每次提交都被测量；只有被选择的改变才会留下。** | 没有选择，变化只是漂移 | 凭感觉采纳改动；用模型的自我报告做优化目标 |
| **五、目的和最高规则来自人；规则不能被它约束的对象修改。** | 目的来自系统之外 | 系统自定终极目标；被裁决者修改裁决者 |

五条之外的一切都不是宪法。宪法里没有 Graph、Plugin、Agent 或大模型这些词：它们是在宪法下建起的第一批东西，可以改变，可以消失。

修改宪法只能由人进行，而且应当极少发生。若某个需求必须增加第六条，先怀疑需求，再怀疑宪法。

## 2. 原语：六种东西

宪法推出的全部基本类型。系统里的任何东西，要么是其中之一，要么由它们组成。

### 2.1 资源

有身份、有版本、有唯一所有者的东西。Graph、Plugin、Run、Session、案例、校验器、旋钮配置都是资源。

- **一个事实只有一个写入者。** 判据：不存在同一个问题有两个地方都能独立修改答案。多个存储不是问题，多个写入者才是。
- 每个所有者用自己的方式存储当前状态，并为自己的资源保留只追加的裁决历史。宪法统一的是协议，不是存储；系统没有全局唯一的日志。

### 2.2 提交

改变资源的唯一方式。

```text
提议者填写：
  目标      资源 ID + 提议者看到的版本
  动作      写入 | 申请 | 执行 | 结算
  内容      可以是自然语言、文件或结构化数据
  证据      对产物与观察记录的引用

宿主盖章（提议者不能填写）：
  提议者身份、授权快照摘要、所属任务、时间、
  自上一次提交以来的成本、旋钮版本
```

四个动作，对应提议者能对世界做的全部事情：

| 动作 | 含义 | 现有工具中的例子 |
| --- | --- | --- |
| 写入 | 改变一个资源 | 保存 Graph、安装 Plugin、提交节点产物 |
| 申请 | 向更高一层要授权或信息 | 联网授权、挂载、凭据输入、向人提问 |
| 执行 | 对外部世界产生副作用 | 发送消息、调用业务系统 |
| 结算 | 结束一个任务 | final_result |

读取不是提交：它不改变事实。读取仍受授权约束，并被记录为观察。**过程自由，只有改变世界的那一刻受约束。**

### 2.3 裁决

每个提交得到一个裁决，包含两个独立的维度和一个原因码：

| 维度 | 取值 | 回答的问题 |
| --- | --- | --- |
| 生效 | 接受 / 打回 / 拒绝 / 待定 | 这个改变能否生效 |
| 验证 | 机械验证 / 有证据引用 / 仅断言 / 独立评审 | 内容经过了什么验证 |

两个维度不能合并。"接受"只表示获准生效，从不表示内容正确。任何呈现给人的结果都必须同时显示两个维度。

原因码是封闭的分类表，由代码给出，不由模型总结。"未能分类"本身是一个码，它的比例上升意味着分类表缺了东西。

裁决由该资源的**校验器**做出。校验器本身是资源，修改它是对上一层的提交。递归到顶层是人。

### 2.4 效果

"执行"类提交对外部世界的影响。外部世界在系统之外，所以效果有自己的生命周期：

```text
获准 → 已开始 → 已观察（成功 / 失败）
                ↘ 未知
```

- 每个效果带幂等标识。
- **未知是一个正当的终点**，不是错误。对同一目标再次产生效果之前，必须先核查；永不自动重放。
- 系统只保证对外部世界的认知诚实，不保证外部世界可控。

### 2.5 任务

一份有界的责任：一个所有者、一份预算、一个必然发生的结算。

- 结算恰好发生一次，结果是：**完成 / 失败（带原因码）/ 上报 / 未知**。
- 预算耗尽本身就是一种结算，不是挂起。
- 上报把责任交还给任务的所有者，递归向上，顶层是人。上报是诚实的失败，不是异常。
- 任务可以嵌套：子任务的结算是父任务的一个观察。

### 2.6 测量

每个裁决、效果和结算，在发生的那一刻由宿主产生一个测量点：

```text
坐标：组件 × 旋钮版本 × 任务类别 × 模型
数值：成本、耗时、裁决、原因码、碰撞次数、恢复距离、事后回填的最终结果
```

测量是投影：它从各所有者的记录派生，可以随时重建，不在主路径上写入，也不是任何事实的来源。它是系统的性能计数器。

## 3. 内核：只做四件事

```text
裁决   提交 → 找到目标资源的校验器 → 裁决（并检查授权只下降）
记录   裁决、效果、观察 → 所有者只追加的历史
结算   任务 → 恰好一次、有限结果、预算封顶
测量   以上一切 → 测量点
```

加上两条不由内核实现、但内核依赖的边界：

- **授权只下降**：任何授权都来自上一层的授予。提交内容、模型输出、Plugin 声明都不能产生授权。
- **沙箱是世界的边界**：所有效果都经过沙箱或其等价物。沙箱外是"未知"的来源。

内核不知道任何业务、协议、模型、工作流套路或组织结构。

## 4. 分层

```text
┌──────────────────────────────────────────────────────┐
│ 实例：Graph、Plugin、案例、业务校验器、优化器          │  人与 Agent 通过提交修改
├──────────────────────────────────────────────────────┤
│ 旋钮：平台参数（有版本、可回滚）                       │  由选择门禁自动采纳
├──────────────────────────────────────────────────────┤
│ 机制：执行器、校验器库、存储、沙箱、调度              │  Agent 可提议，人批准
├──────────────────────────────────────────────────────┤
│ 内核：裁决 · 记录 · 结算 · 测量                        │  Agent 可提议，人批准
├──────────────────────────────────────────────────────┤
│ 宪法：五条                                             │  只有人能修改
└──────────────────────────────────────────────────────┘
  边缘适配：企业微信、PyPI、HTTP、界面、旧格式兼容      可以凌乱，必须可整块替换
```

- 越往下越小、越稳定；越往上越大、越活跃。
- 每一层的修改，都是由下一层规则裁决的提交。
- **边缘允许凌乱，但凌乱不能渗进核心。** 兼容旧格式的代码属于边缘，必须登记退役条件。

## 5. 舞台上的对象如何由原语表达

| 对象 | 由什么组成 |
| --- | --- |
| **Run** | 一个任务资源。它的状态是"当前接受哪些提交" |
| **Graph** | Run 的校验器：一个状态机，规定每个状态下接受哪些提交。**它规定什么结果会被接受，不指挥谁先做什么** |
| **AgentNode** | 一个执行器，在 Graph 某个状态下提出提交 |
| **OpNode** | 确定性的提议者，或确定性的校验器 |
| **Plugin** | 一个资源，携带能力与对外的效果端点；它的声明不能扩大授权 |
| **Artifact** | 一次写入提交被接受后的不可变内容 |
| **Session** | 人与系统之间的长期资源；Turn 是其中的一次申请 |
| **人的确认** | 一个处于"待定"的裁决，由人作为校验器完成 |
| **Pilot** | 一个拥有管理类授权的执行器，和其他执行器遵守同一协议 |

**Graph 的严格程度是一个旋钮。** 最严时每一步都规定好；最松时只规定最终的结算契约。模型越强，旋钮越往松的方向走。细腰不变，确定性不变，架构不需要为更强的模型改变。

## 6. 学习：系统如何变好

### 6.1 信号

梯度不来自大模型阅读记录，而来自测量点上的统计，以常数成本在执行时产生。可以直接读出的量：

| 量 | 含义 | 指向 |
| --- | --- | --- |
| 碰撞率 | 哪类拒绝反复出现 | 系统属性，而非模型噪声 |
| 恢复距离 | 碰壁后几步走通 | 错误信息的质量 |
| 跨会话重复碰撞 | 每个新会话都要重新撞同一堵墙 | 这条知识应成为舞台的一部分 |
| 从未被使用的能力 | 死重量 | 删除候选 |
| 反复寻找不存在的东西 | 需求驱动的缺口 | 唯一由数据提出的加法 |
| 每个被接受结果的成本 | 被打回和失败的成本计入分子，不计入分母 | 主目标 |

**质量是约束，效率是目标。** 任何效率指标都不能脱离"被接受的结果"单独优化。

### 6.2 旋钮

平台上少数几个承载"怎么把事做好"的自由度。旋钮是资源，有版本，可回滚。候选（假设，由数据检验）：

| 候选 | 一端 | 另一端 |
| --- | --- | --- |
| 结构严格程度 | 每一步都规定 | 只规定结算契约 |
| 校验强度 | 只校验形式 | 多重独立校验 |
| 上下文预载 | 初始给足 | 只给入口，按需发现 |
| 预算 | 少 | 多 |
| 分解宽度 | 单个执行器 | 多路并行 |
| 模型档位 | 小而快 | 大而强 |
| 人介入门槛 | 多数事请人确认 | 仅高风险上报 |

一个候选是真旋钮，须同时满足：**敏感**（拧它结果会变）、**因任务而异**（不同任务的最优值不同）、**大致平滑**（相邻取值结果相近）。不满足的，固定为常数或删除。

判定必须满足两条统计纪律（来自 [概念验证](../experiments/constitution-poc/README.md) E3）：按任务类别的检验次数做多重比较校正，否则占位修改被误判为有效的比例明显上升；每个类别需要足够的样本，数据不足时判定会偏向更简单的结论，可能错过真旋钮。

### 6.3 策略与选择

- **策略**：从任务描述到旋钮取值的映射。可以从朴素开始：默认值，再到由数据挑出的少量规则，再到由模型在上下文中选择，再到学习得到的模型。旋钮与信号对了，策略可以逐级升级，核心不变。
- **选择门禁**：确定性代码。在提议者看不到的保留案例上，以相同运行次数、多次重复评估；质量不退化且主目标显著改善，才接受新的旋钮版本。门禁规则由人制定，优化器不能修改。
- **案例**：来自真实 Run 的冻结输入与结果，只追加。保留集由权限隔离，而不是由指令约束。

### 6.4 递归

旋钮集合本身也接受数据的检验：

- 一个旋钮总被设成同一个值 → 它不是旋钮，删掉。
- 两个旋钮总是一起动 → 可能是同一个维度，合并。
- 一部分结果差异无法被现有旋钮解释 → 缺了一个维度，由人寻找新的坐标。

**架构的复杂度由证据收敛，而不是由人的判断删减。**

### 6.5 大模型在学习中的位置

不是阅读者，而是在信号最陡处动手的人：对排名最靠前的异常解释原因、提出一处改动。花费由预算决定，与数据量无关。另以固定预算随机抽样审查普通记录，防止信号体系的盲区。

## 7. 极限检验

| 组件 | 智能无限 | 规模无限 | 时间无限 | 存在对手 |
| --- | --- | --- | --- | --- |
| 提议与裁决分离 | 成立（利益冲突与智力无关） | 成立 | 成立 | 这正是它存在的理由 |
| 只追加、未知即未知 | 成立 | 按所有者分区，线性 | 成立；无迁移负担，因为不改写 | 成立 |
| 有限结算 | 成立（资源总是有限） | 成立 | 成立 | 防止拖死系统 |
| 测量与选择 | 成立 | 统计成本线性，分析成本由预算封顶 | 案例库单调增长 | 保留集与门禁不可被提议者修改 |
| 人定目的 | 成立（智能回答"怎么做"，不回答"为了什么"） | 成立 | 成立 | 成立 |
| 细腰协议 | 成立 | 每个参与者只需理解协议，成本 N 而非 N² | 协议极少变化 | 每次提交都经裁决 |
| Graph 严格度 | 旋钮调松，架构不变 | 成立 | 成立 | 由校验器保证 |
| 旋钮 | 不需要的旋钮被数据删除 | 跨 Graph 数据越多越准 | 由选择持续更新 | 门禁守护 |
| 边缘适配 | 不受影响 | 各自扩展 | 有退役期限 | 不进入核心 |

不能通过这张表的东西不属于核心。

## 8. 刻意不做的事

- 不建 Agent loop、记忆系统、计划系统；执行器自带它们，核心不需要。
- 不建全局日志或事件溯源；协议统一，存储归各所有者。
- 不在核心里写操作步骤式的指令；那是镊子，属于旋钮或 Plugin。
- 不建由大模型通读全部记录的分析者；分析由统计完成。
- 不在核心里编码组织结构、业务领域或工作流套路。
- 不保留没有退役条件的兼容分支。
- 不让任何指标在脱离"被接受的结果"时成为目标。

## 9. 与现有 Anchor 的对应

| 现有 | 在本架构中 | 处理 |
| --- | --- | --- |
| Kernel：GraphRunner、执行端口、Artifact 端口 | 内核与机制 | 保留 |
| final_result | 结算提交 | 推广为通用协议 |
| 原生确认（安装、删除） | 待定裁决，人是校验器 | 推广 |
| Kernel 编译 Graph | Graph 资源的校验器 | 保留 |
| `session_network`、`plugin_mount`、`credential_request`、`ask_user` | 申请提交 | 统一形状 |
| 业务 MCP 工具、投递账本、`Uncertain` | 执行提交与效果生命周期 | 保留语义，统一形状 |
| bwrap 沙箱、授权快照冻结 | 世界边界、授权只下降 | 保留 |
| Run 状态与 stop/resume/retire/abandon | 任务资源 + 控制类提交 + "当前实例"指针 | 概念验证 E2：按文档转写的规则可由三条定律加一个指针推出，穷举仅 2 处分歧，均为退役后的操作（现有规则允许退役后 abandon）。需对照真实代码核实，并由用户决定该语义 |
| `goose_acp/usage.rs` | 测量的原始来源 | 保留，接入测量投影 |
| RSI Graph | 优化器的一个实例 | 输入改为读取测量；输出改为旋钮或实例的提交 |
| 工具披露阈值等环境变量与常量 | 旋钮候选 | 资源化 |
| Pilot 默认指令中的操作步骤 | 镊子 | 下沉为 Plugin 或旋钮；只保留边界说明 |
| 旧格式兼容分支 | 边缘适配 | 登记并设退役条件 |

## 10. 迁移顺序

不重写。每一步都不改变已有行为，除非明确标注。

| 阶段 | 内容 | 依据 |
| --- | --- | --- |
| M0 | [收敛方案](convergence-development-plan.md) W1：为终态与存活状态命名 | 一个事实一个定义 |
| M1 | 原因码表与测量投影（收敛方案 W5） | 宪法第四条的地基 |
| M2 | 映射报告：现有每类状态变化对应哪种提交、哪种裁决、哪个写入者；找出同一事实的多个写入者 | 第 2 节的检验 |
| M3 | 新增的状态变化只以提交实现 | 细腰开始生长 |
| M4 | 必然结算：默认预算与上报结算（收敛方案 W4，需用户决定） | 宪法第三条 |
| M5 | 旋钮资源化、案例库、选择门禁，用一个旋钮跑通第一个闭环 | 宪法第四条闭环 |
| M6 | 逐条收编旧路径，从 final_result 开始 | 删除本轮 |

**判断迁移是否正确的标准**：同一规则的独立判断点数量在下降；核心里没有加入任何通不过第 7 节检验的东西。代码行数不是标准。

## 11. 只能由数据或人回答的问题

| 问题 | 由谁回答 |
| --- | --- |
| 真正的旋钮是哪几个 | 数据（第 6.2 节的三个条件） |
| "任务类别"这个坐标如何定义 | 数据；可能需要由模型学习出的表示 |
| 哪些内容能被机械验证，哪些只能评审 | 逐个领域的实践 |
| 跨多个资源的提交需要怎样的一致性 | 出现真实需求时设计，不预建 |
| 系统自主调整的上限在哪一层 | 人（宪法第五条） |
| 对企业而言"确定性"的具体含义 | 真实用户 |

---

## 12. 如何持续知道它仍然是对的

- **新功能检验**：能否表达为一个新实例（Graph、Plugin、校验器、案例）？能，就不碰核心。必须改核心，先停下来：这可能意味着缺了一条定律，也可能意味着需求本身有问题。
- **组件检验**：任何组件，要么能从宪法推出，要么属于可整块替换的边缘。两者都不是的，是删除候选。
- **极限检验**：每次核心改动都过一遍第 7 节的四个极限。
- **数据检验**：旋钮的增删合并、校验器的漏检率、"未能分类"的比例，定期由测量回答。
- **压缩检验**：Anchor 应当始终能用第 1 节那一句话说明。做不到的那一天，就是核心开始腐化的那一天。
