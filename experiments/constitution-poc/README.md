# constitution-poc：宪法的概念验证

[docs/anchor-constitution.md](../../docs/anchor-constitution.md) 的概念验证。独立的 Rust crate，不依赖、也不影响 Anchor workspace，无外部依赖，所有随机过程固定种子、结果可复现。

```sh
cargo test                              # 21 项断言
cargo run --release --bin report        # 打印下文全部数字
cargo clippy --all-targets -- -D warnings
```

## 要回答的问题

| 实验 | 假设 | 可被什么证伪 |
| --- | --- | --- |
| E1 原语 | 六种原语加只做四件事的内核，能表达 Anchor 现有的关键行为，而且每条规则都来自宪法，不需要特例 | 某个行为必须在内核里写业务特例才能表达 |
| E2 生命周期 | Run 的 stop / resume / retire / abandon 及其各自的前置条件，可以由三条定律加一个指针推出 | 穷举对比出现大量分歧，或分歧需要新增规则才能消除 |
| E3 测量与选择 | 不让模型读任何记录，只靠探针计数和确定性门禁，就能找出问题、拒绝假改进、判断旋钮是否存在 | 门禁接受占位修改的比例远高于显著性水平；计数排不出真实的问题顺序 |
| E4 规模 | 裁决成本不随规模增长；测量的内存与事件数无关 | 单次提交成本随资源数或提交数明显增长 |

## 结构

| 文件 | 内容 |
| --- | --- |
| `src/kernel.rs` | 六种原语与内核：`submit` 是唯一的改变入口，内部只做裁决、记录、结算、测量。另含几个示例校验器：`ReviewGraph`（Graph 作为 Run 的校验器）、`Library`（需要人确认的安装）、`Endpoint`（对外发送） |
| `src/lifecycle.rs` | 按文档转写的现有生命周期规则 `Documented`，由宪法推出的 `Derived`，以及对两者乘积状态的穷举探索 |
| `src/measure.rs` | 流式聚合器、配对置换检验、Spearman 相关 |
| `src/sim.rs` | 一个会撞到隐藏墙壁的随机提议者、确定性选择门禁、旋钮分析、学到的策略 |
| `tests/e1_*.rs` `e2_*.rs` `e3_*.rs` | 每条主张对应的断言 |
| `src/bin/report.rs` | 运行全部实验并输出结果 |

几个设计上的要点，都是"让违规无法表达"，而不是事后检查：

- `Submission` 没有身份、成本、授权、批准、时间这些字段。提议者想伪造也没有地方填。
- `Stamp` 的字段是私有的，只能在内核里构造。
- 裁决的两个维度是两个独立的类型 `Effect` 和 `Verification`，"接受"在类型上就无法表示"正确"。

## 结果

### E1：原语能表达现有行为（12/12 通过）

| 现有 Anchor 行为 | 在原语中如何表达 | 结果 |
| --- | --- | --- |
| final_result：普通回答、看似正确的 JSON 都不算完成 | 节点完成是一次写入提交，由 Graph 校验器裁决 | 纯文本被打回（`CompletionInvalid`）；非法路由被打回 |
| Graph 编排与反馈边 | Graph 是 Run 的校验器，规定每个状态接受什么 | 越序提交被拒绝；write → review → revise → review → publish → settle 走通 |
| Graph 严格程度 | 同一内核，换一个 `Strictness` | 宽松模式只校验最终交付契约，内核零改动 |
| "接受"不等于"正确" | 验证是独立维度 | 无证据为"仅断言"；引用了 `check=pass` 的观察为"机械验证" |
| Plugin 安装的原生确认 | 待定裁决，人是校验器 | 模型自己批准被拒（`HumanOnly`）；人批准后才生效 |
| 确认绑定精确目标 | 待定变更记录它看到的版本 | 目标在等待期间被改，旧批准被拒（`PendingTargetChanged`） |
| 结果未知的外部效果不自动重放 | 效果生命周期，"未知"阻断同一端点的下一次执行 | 第二次发送被拒，世界没有收到；没有观察作证据的"成功"声明被打回 |
| 任务必然结束 | 预算耗尽本身是结算 | 超预算后结算为失败，之后的提交一律拒绝 |
| Pilot 不能修改定义它自己的 Graph | **不需要专门的规则**：被某个校验器裁决过的主体，永远不能修改它 | 被拒（`SelfJudgement`）；从未被它裁决过的主体也只能提议，最终仍需人 |
| 授权只下降 | 只能授出自己持有的授权；提交内容不能产生授权 | 越权授予失败；在提交里写授权无效 |
| 乐观并发 | 提交声明它看到的版本 | 过期视图被打回，不静默合并 |
| 一切被记录和测量 | 每次裁决（含拒绝）产生记录和测量点 | 历史与探针计数一致 |

最值得注意的是"Pilot 不能修改自己的 Graph"：在 Anchor 里它是一条单独的规则，在这里它从第五条宪法自动推出，内核中没有任何针对它的代码。

### E2：生命周期能坍缩，只有两处分歧

`Derived` 自己没有任何生命周期规则，只有：任务（执行中、已暂停、已结算一次）、Session 拥有的"当前实例"指针、效果生命周期，以及三条定律：已结算不可逆、未知效果在被观察之前阻断、任务只结算一次。

穷举两个模型的乘积状态：**19 个可达状态、190 次转移，只有 2 处分歧**，而且都在同一个位置：对一个已暂停后又被退役的 Run 再做操作。

| 事件序列 | 现有规则 | 推导模型 |
| --- | --- | --- |
| 暂停 → 退役 → 再次 stop | 接受（空操作，见假设 A1） | 拒绝 |
| 暂停 → 退役 → abandon | 接受，状态变为 Aborted | 拒绝 |

原因很清楚：现有规则把"已退役"当作一个只有 resume 会检查的标记；推导模型把退役当作一次结算，于是"退役后不能恢复"不再需要单独的规则，由不可逆性自动得到，代价是退役后也不能再 abandon。

**这需要你决定**：退役之后还允许 abandon，是一个有意的功能，还是一个没被注意到的副作用？如果是后者，推导模型更简单，也更一致。

另外两条规则同样不需要专门的代码：

- 退役后不能 resume：由"已结算不可逆"推出。
- 有未确认投递时不能退役：由效果定律推出，和阻断第二次发送的是同一条规则。

### E3：不让模型读记录，也能诊断和选择

模拟的提议者在一个有 6 堵隐藏墙壁的沙箱里工作。**提议者的行为是假设的模型；探针、统计和门禁是被测试的真实代码。**

**诊断（2000 个会话，只靠计数）**

| 墙 | 真实命中概率 | 碰撞次数 | 至少撞过一次的会话比例 |
| --- | --- | --- | --- |
| 0 | 0.12 | 1889 | 88.3% |
| 1 | 0.08 | 1681 | 79.4% |
| 2 | 0.05 | 1402 | 66.0% |
| 3 | 0.03 | 942 | 45.6% |
| 4 | 0.015 | 618 | 30.3% |
| 5 | 0.005 | 263 | 13.1% |

- 按碰撞次数排出的顺序与真实顺序完全一致（Spearman = 1.00）。
- 恢复距离直接度量了错误信息的质量：简短的错误信息平均 2.76 步才走通，有指导性的是 1.25 步。
- 88% 的会话都要为最常见的那堵墙重新付一次代价：这条知识应该成为舞台的一部分。

**选择门禁（200 个保留案例 × 3 次重复，α = 0.05）**

| 候选修改 | 确定性门禁 | "跑一次，数字更好就保留" |
| --- | --- | --- |
| 有指导性的错误信息（真实改进） | 接受 20/20 | — |
| 无行为影响的修改（占位） | 接受 9/200（4.5%） | 接受 99/200（49.5%） |

后一列就是许多 RSI 系统的采纳规则。它对一个毫无作用的修改，有一半的概率宣布"改进成功"。

**古德哈特修改（第一次被拒就放弃）**：每个会话的成本从 96.9 降到 11.9，碰撞也大幅下降，单看效率指标是巨大的进步；但接受率从 0.818 降到 0.021，每个被接受结果的成本从 118.5 升到 555.6。门禁拒绝了它。这验证了"质量是约束，效率是目标"。

**旋钮是否存在，由数据决定**

| 候选旋钮 | 每类样本数 | 短任务 | 长任务 | 判定 |
| --- | --- | --- | --- | --- |
| 有指导性的错误信息 | 1000 | +6.09（p=0.002） | +24.42（p=0.002） | 常量：处处更好，固定下来，不再作为旋钮 |
| 占位修改 | 1000 | +0.46（p=0.028） | +0.83（p=0.486） | 删除：没有可测量的作用 |
| 预载墙壁信息 | 1000 | −1.47（p=0.002） | +5.07（p=0.002） | 真旋钮：短任务有害、长任务有益 |
| 预载墙壁信息 | 300 | −1.06（p=0.006） | +2.17（p=0.312） | 常量（误判，数据不足） |

**学到的策略**（任务长度超过阈值才预载；数值为每个被接受结果的成本，越低越好）

| 训练样本 | 阈值 | 学到的策略 | 一律开启 | 一律关闭 |
| --- | --- | --- | --- | --- |
| 300 | 24 | 98.90 | 98.48 | 100.92 |
| 2000 | 10 | 98.28 | 98.48 | 100.92 |

### E4：规模

| 资源数 | 提交数 | 保留历史 | 耗时 | 单次提交 | 探针键数 |
| --- | --- | --- | --- | --- | --- |
| 1,000 | 100,000 | 否 | 39 ms | 392 ns | 3 |
| 10,000 | 1,000,000 | 否 | 433 ms | 432 ns | 3 |
| 100,000 | 1,000,000 | 否 | 487 ms | 486 ns | 3 |
| 10,000 | 1,000,000 | 是 | 722 ms | 721 ns | 3 |

资源数增加 100 倍，单次提交成本只增加约 24%（有序映射的对数增长）。探针的内存只取决于不同键的数量，与事件数无关。耗时数字因机器而异，以上是一次运行的结果。

## 实验中暴露的、事先没有想到的问题

这些是这次验证最有价值的部分，因为它们修正了宪法文档里的说法：

1. **旋钮分析必须做多重比较校正。** 每个旋钮要在多个任务类别上各检验一次，不校正时，占位修改被误判为"有效"的比例是 6/100，相当于给了噪声多次被当真的机会。按检验次数做 Bonferroni 校正后降到 2/100。原先的测试正是因为这一点失败的，修正的是方法，不是测试。
2. **判断旋钮是否存在需要足够的数据。** 预载在每类 300 个样本时测不出来，1000 个以上才显著。数据不足时，分析会倾向于更简单的结论（常量），方向与"做减法"一致，但会错过真正的旋钮。
3. **学到的策略不一定有用。** 在这个环境里，策略只在训练数据充足时才略优于固定取值；数据少时反而不如"一律开启"。旋钮真实存在，不等于值得为它学习一个策略。
4. **生命周期的推导暴露了一个现有语义问题。** 见 E2：退役后还能 abandon，现有文档没有说明这是不是有意的。

## 这次验证没有证明的东西

- **提议者是模拟的，不是大模型。** E3 证明的是：如果提议者有这样的统计行为，测量和门禁能正确工作。真实模型的行为分布需要用 Anchor 的真实 Run 数据来检验。
- **`Documented` 是从文档转写的，不是从代码提取的。** 其中有三处是文档没说明、由我做出的假设（代码注释中标为 A1、A3、A4）。E2 的两处分歧中，有一处直接取决于假设 A1。要把这个结论用于 Anchor，需要对照 `application/control.rs`、`assistants.rs`、`abandon.rs` 的真实代码核实。
- **内核是内存中的。** 没有持久化、没有并发、没有崩溃恢复、没有跨资源的原子提交。这些正是生产系统最难的部分，PoC 没有覆盖。
- **校验器是示例性的。** 现实中最难的是为自然语言内容写出可靠的校验器，PoC 只用了结构化字段和"检查通过"的观察。
- **只有四个动作、一种原因码表。** 它们是否足以覆盖 Anchor 全部的状态变化，需要做 M2 映射报告。

## 结论

| 假设 | 结论 |
| --- | --- |
| E1 原语足以表达现有行为 | **成立**（在所测的 12 种行为上）。其中一条现有特例规则由宪法自动推出 |
| E2 生命周期可以坍缩 | **基本成立**。四个动词的全部前置条件由三条定律加一个指针推出，只有 2 处分歧，集中在一个需要你做决定的语义上 |
| E3 不读记录也能诊断和选择 | **在模拟环境中成立**。附带两条方法上的必要条件：多重比较校正、最低样本量 |
| E4 规模 | **成立**（在内存中、单线程的前提下） |

下一步要把 PoC 的结论用到 Anchor 本身，需要做的是 M2：拿真实代码核实 E2 的假设，并把现有的全部状态变化逐一映射到四个动作上。
